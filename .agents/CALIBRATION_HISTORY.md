# Історія математики калібрування мікрофона — що пробували, куди поверталися, де що лежить

> Українською навмисно: це документ для рішень власника — де відкочувати, а де йти далі.
> Кожен поворот — із комітами, щоб не винаходити знайдене й не загубити набуте.
> Чинний стан коду — в кінці, разом із діагнозом «чому профіль виходить пласким».

Предмет один: **крива компенсації мікрофона** (`estimateMicCompensation` у `cpp/sweep.cpp`) і те, що
з неї робить синтез (`synthesizeAutoEq16`). Ключова формула, через яку помилка знака коштує так
дорого:

```
m[b] = avgClean16[b] + micComp16[b]        // тиск, який синтез вважає реальним
deltaDb = target − (m[b] − refMid)         // корекція еквалайзера
```

⇒ **Завищена компенсація змушує еквалайзер РІЗАТИ.** Саме тому «мікрофон глухий знизу, додамо йому»
обертається вирізаним басом.

---

## Спроба 1 — «якір cabin gain» (10–12.09)

**Коміти:** `8ebfed9` (калібрування мікрофона, спектральне віднімання, GCC-PHAT у C++, 10.09) →
`ec3089d`, `9d51ba5`, `b66a604`, `202236e`, `ef7e8c6`, `31f9558`, `148e252`, `cb8dae8` (усі 10.09) →
`c70517b` (12.09, точка відновлення).

**Що робили.** Очікували, що в салоні тиск знизу **росте** (+6 дБ/окт нижче 80 Гц), і кожен децибел
нестачі відносно цього очікування писали капсулю. Стеля компенсації — 8 дБ, виведена з **однієї**
ланки вхідного фільтра (0.47 мкФ на 2.2 кОм, 1-й порядок, 154 Гц).

**Що вийшло.** Крива `+16 +16 +16 …` — три нижні смуги **в затиску**. Насичена оцінка це не вимір.
Синтез читав це як «у салоні надлишок баса» і **різав реальний бас**.

**Чому зламалося.** Калібрування свіпило **двері з мовчазним сабом**, тож природний спад дверей на
20–80 Гц приписувався мікрофону. Причина була у **вимірі**, а не у фізиці.

## Спроба 2 — «фізика + правильний вимір» (13.09)

**Коміти, по порядку:** `7110bb9` → `a31a78d` → `549e2a2`. Плюс `2edc44a`, `983fb8f`, `cd449c1`,
`fed45ee`, `98be8ad`, `d5eb117`, `555c4b9`, `fff1481`, `77b0e2c`, `624fc66`, `e2a4569` — звіт,
геометрія саба, утримання мікрофона.

**Три кроки, і середній несучий:**

1. `7110bb9` **«Measure the car instead of the correction»** — прибрав очікування cabin gain,
   занулив смуги 0–2, обмежив 3–4 стелею 8 дБ. ⚠️ Це було **лікування не того боку**: прибрали
   фізику замість полагодити вимір.
2. `a31a78d` **«Sweep the subwoofer during microphone calibration, and take the best channel»** —
   саб грає під час калібрування, оцінка бере **максимум по каналах**, кожен нормований на власну
   середину. Без цього крок 3 був би косметикою: середнє з чотирьох дверей і одного саба розчиняє
   єдине джерело, здатне дати низ.
3. `549e2a2` **«Use the physics we already have»** — матриця конструктиву з `ROOM_CALIBRATION.md`
   §24 стала **основою** кривої; якір cabin gain повернуто; стеля порахована з **обох** ланок
   фільтра (1-й порядок 154 Гц + 2-й порядок 120 Гц ≈ −14.5 дБ на 80 Гц проти виміряних −14.1);
   відмова — за **виміряним SNR**, а не за номером смуги; **виміряна оцінка верху видалена** (вона
   брала 5 кГц за опору й писала капсулю все, чого бракує вище).

**Що вийшло.** Крива
`+29.8 +24.7 +18.7 +16.2 +8.9 0 0 0 0 0 −1.5 −5.0 −1.0 +3.5 +7.0 +10.0`,
**відтворена чотири проходи поспіль із розкидом 0.3 дБ** — зокрема на проході з покаліченим
мікрофоном, бо смуги, що вирішують, не залежать від верху.

**Спростована передумова, на якій трималася спроба 1.** §24 стверджувала, що на 20–31.5 Гц сигнал
тоне під тепловим шумом АЦП (SNR ≤ 0 дБ). Наш звіт: **50 дБ**. Смуги не були мертві — **їх
оголосили мертвими**.

## Спроба 3 — «довіряти лише тому, що свіп підтвердив» (15 і 21.09) — ЧИННА

**Коміти 15.09:** `1369335` (вікно імпульсу відкрите до першого приходу — його обрізання з'їдало
найглибші смуги дверей), `2d5717c` (кожна смуга міряється по тому, що свіп у ній збудив; 20 Гц і
20 кГц перестали читатися пласкими).

**Коміти 21.09:** `4d0a77c` (насичення = **невідомо**, а не «запиши стелю»; верх матриці лише за
підтвердженням) → `f5aaae3` (одне місце обробляє конструктив) → `e13f38a` (клас `MicProfile`:
конструктив + розміщення) → `5ad92ae` (**«the cabin is no longer assumed»** — якір cabin gain
прибрано **вдруге**; капсулю дістається лише те, що **вузьке й спільне** для всіх каналів).

**Навіщо це робили — причини справжні, і їх не можна просто відкинути:**

- На проході 20.09 **кожна** нижня смуга сіла точно на свою стелю (`+52.8` проти стелі 52.8, `+40.5`
  проти 41.1). Це не «мікрофон глушить 20 Гц на 52.8 дБ», це «дефіцит більший за все, що вхідний
  тракт може пояснити». Записати стелю — це знову спровокувати різання баса.
- **Третій свідок:** живий рожевий шум 14.09 (`compare_modes.py`, мікрофон проти розрахункового)
  після переходу на усереднення по потужності дав розбіжність угорі **+0.9 / +1.4 / +2.1 дБ**. Тобто
  дефіциту 7–10 дБ, який прописувала матриця, **немає**. Метод незалежний від свіпу — це вагомий
  доказ.
- Слово власника 21.09: *«мікрофон чує бас добре, навіть коли він не в салоні, а Harman виходить
  трохи басовитим — можливо, мікрофон заслуговує трохи більше довіри»*.
- Cabin gain справедливий лише в **герметичному** салоні: стенд — відкритий простір, кабріолет —
  відкритий, автобус — не седан із документа. Ми не питаємо, що в людини, отже не можемо це
  припускати.

## 🔴 Чинний стан і діагноз: чому профіль виходить ПЛАСКИМ

Пласкість дає не одна правка, а **дві незалежні межі, що зійшлися**.

**Низ (смуги 0–4), `sweep.cpp` ~рядок 683:**
```cpp
if (deficit >= ceiling) { outStatus16[b] = kMicBandUnknown; continue; }  // лишається значення матриці
```
Якщо дефіцит дійшов до стелі — смуга оголошується **невідомою** й лишається на цифрі конструктиву
(для Pinhole це `0 0 0 +2 0`). На проходах, де низ слабкий, це спрацьовує **на всіх** нижніх смугах.

**Середина й верх (смуги 5–15), `sweep.cpp` ~рядок 820:**
```cpp
const bool capsuleCanSpeakHere = kHwCenters[b] >= 10000.0f;
if (table == 0.0f)                        value = capsuleCanSpeakHere ? measured : 0.0f;
else if (знак measured == знак table)     value = min(|measured|, |table|);
else                                      value = 0.0f;
```
- Де матриця каже `0` (смуги 5–9) — **нижче 10 кГц вимір не має права говорити взагалі** → `0`.
- Де матриця каже щось (10–15) — застосовується **лише якщо вимір підтвердив той самий знак**, і
  обрізається до **меншого** з двох.
- Не підтвердив — `0`.

⇒ У сумі: низ «невідомий», середина заборонена, верх обрізаний до нуля, якщо огинаюча не підтвердила.
**Профіль плаский, вади акустики не компенсуються.**

## Де відкочувати, а де йти далі — моя порада

**Не відкочувати цілком до спроби 2.** Там жили дві доведено хибні речі: запис стелі як виміру
(`+52.8`) і незалежно спростований рожевим шумом підйом верху `+3.5 / +7 / +10`.

**Що варте повернення зі спроби 2:**

1. **Якір cabin gain — але за запитанням, а не за припущенням.** Саме це й написано в коментарі
   `5ad92ae` як умова повернення: спитати **простір** (закритий/відкритий і яка довжина), бо перехід
   ≈ `565 / найбільший розмір у футах`. Ми вже питаємо тип кузова, але це питання про **посадку**, а
   не про те, чи є дах. ⇒ Одне нове питання в майстрі — і якір повертається законно.
2. **Правило «нижче 10 кГц вимір мовчить» — надто широке.** Воно вбило смуги 5–9 назавжди. Але
   міркування під ним правильне: кімнатна мода на позиції мікрофона теж спільна для всіх каналів.
   ⇒ Розділяти не за частотою, а за **шириною**: вузький спільний провал — капсуль, широкий —
   кімната. Матеріал для цього вже є ([[TODO.md]] п. «полярність по смугах», той самий апарат).
3. **«Невідомо» має бути видимим, а не тихим.** Зараз смуга просто лишається на цифрі матриці й
   пише статус у звіт. Людина бачить плаский профіль і не знає, що це відмова, а не результат.
   ⇒ Інформаційна сторінка після калібрування (вже в `TODO.md`) має казати про це словами.

**Чого НЕ повертати:** матрицю верху `+3.5 / +7 / +10` без підтвердження — спростована рожевим
шумом; запис стелі як виміру — спростований проходом 20.09.
